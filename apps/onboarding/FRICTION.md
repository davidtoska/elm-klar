# Friction log: Supplier onboarding

Columns: id, app, module, kind, what happened, cost, fix, severity. Kinds and severities
as in [../PLAN.md](../PLAN.md).

| id | app | module | kind | what happened | cost | fix | severity |
|---|---|---|---|---|---|---|---|
| O-001 | onboarding | Klar.Validate | missing | Validators only run on `String`. A required `Select`, `MultiSelect`, `TagInput`, `FileDrop`, `NumberInput` or `Rule` has no validator, so every non-text field needs a hand-written "is it empty?" check, and the result must be turned into the `{ field, message }` shape of `Validate.Error` by hand. | ~15 min of design, a helper per field kind | `Validate.requiredValue : String -> Maybe a -> Maybe Error` (and `nonEmptyList`), or each stateful component exposing `isEmpty`. | slow |
| O-002 | onboarding | Klar.Rule, Klar.RuleBuilder | type | `Rule.Choice` is `{ value : String, label : String }` and conditions store `List String`. The application's own `CategoryId Int` and `CountryId` cannot go in; I had to write `categoryKey`/`categoryOfKey` (and parse back, with a `Maybe`) in `Domain`. This is the opposite of `Select`, whose options are generic in `id`. | design time + 2 helpers per id type | A generic `choiceField` over the id type with `toKey`/`fromKey` given once, like `Table.rowIds`. | slow |
| O-003 | onboarding | Klar.Stepper, Klar.Form | missing | Nothing connects a multi-step flow: the Stepper is display only, each step needs its own `Form.view`, its own validation, and "go to field X" for a field on another step (review step summary) has to be written by hand: the error summary only knows DOM ids, not steps. | design time, ~60 lines | A documented recipe, or `Form.steps`-style helper that maps a problem to a step. | slow |
| O-004 | onboarding | Klar.Radio | type | `Radio` is `String`-valued (`Radio.option "express" ...`, `onSelect : String -> msg`) while `Select` is generic in the id. A radio over `PaymentTermsId` needs the same key/fromKey dance as the rule builder. | decision time | `Radio` generic like `Select`. | annoy |
| O-005 | onboarding | Klar.Form, Klar.Modal | find | "Leaving a half-filled flow asks for confirmation" has no single answer in the docs: `Form.unsavedChanges` says it is "the job of the application's navigation", `Modal.static`/`onRequestClose` cover dialogs only. I read AppShell, Form, Modal and ConfirmDialog to piece together a route guard. | ~10 min | A short "unsaved changes" recipe in `USING.md` (Browser.application: LinkClicked + UrlChanged + ConfirmDialog). | slow |
| O-006 | onboarding | Klar.Table (module doc) | doc-wrong | The module example uses `Table.text "customer" "Customer" .customer [...]` with a plain string; the real signature is `Table.text : ColumnId -> ...` (USING.md and README have it right). Caught while reading `docs.json` signatures, before compiling. | 2 min | Fix the example in the `Klar.Table` module doc (and run the doc examples through the compiler). | annoy |
| O-007 | onboarding | Klar.AppShell (module doc) | doc-wrong | The example calls `SideNav.item { key = "orders", label = ..., href = ... }`; the real function is `SideNav.item : Keys key -> { key, label, href } -> Entry`. Same for `SideNav.current (pageKey ...)` which needs a typed key. Found by reading signatures first; would have been a compile error. | 3 min | Fix the example; the doc examples are not compiled by any check. | annoy |
| O-008 | onboarding | Klar (README/USING) / elm.json | find | `Browser.application` needs `elm/url` (the `Url` type) as a direct dependency, but the dependency list in USING.md (section 1) has only core/html/browser/json/time and says nothing about elm/url for applications (CONTRIBUTING only says the library itself uses none). First build failed with `MODULE NOT FOUND Url`. Fix was to move `elm/url` from indirect to direct in the app's elm.json. | 1 compile error, 3 min | USING.md section 1 should list `elm/url` for applications that use `Browser.application` (the AppShell doc says "use it as the root of a Browser.application"). | annoy |
| O-009 | onboarding | Klar.RuleBuilder | missing | The summary line under the builder says "All rows" for an empty rule, and the toolbar/summary speak of "rows" and "matches". For a pricing rule ("if category is X and quantity above Y") there are no rows; "All rows" is the wrong sentence and it cannot be changed (`locale` only picks en/nb). | cosmetic, no workaround | A `RuleBuilder.emptyText : String` (and the noun for matches), or a hidden summary (`RuleBuilder.noSummary`). | annoy |
| O-010 | onboarding | Klar.RuleBuilder / Klar.Rule | missing | `Rule.Choice` has no `group` or `description`: my category choice list is flat (11 categories) while the same categories are grouped in the `MultiSelect` on step 1 (`Select.withGroup`). Choice fields cannot carry what an option carries. | design decision | Let `Rule.choiceField` take `Select.Option`s (generic in the id; this also fixes O-002). | annoy |
| O-011 | onboarding | Klar.Toast / Klar.Modal | bug | A danger toast is sticky and sits bottom right over everything. When a modal is open (price rule editor) the toast covers the modal footer ("Save rule" button) until it is closed by hand. I had to close two toasts before I could press Save. The toast stack should shift, or the modal footer should stay clickable. | 1 iteration while testing | Toasts above the modal footer (offset when a modal is open), or `Toast.view` position attribute. | slow |
| O-012 | onboarding | Klar.Form | annoy | `Form.status` inside `Form.actions` next to Back and Save: a long failure message ("Can't reach the service ... Try again") pushes the Back and Save buttons onto a second line at 800px width; the row jumps. | cosmetic | `Form.actions` should let the status take the free space and wrap inside itself, or a `Form.statusRow` above the actions. | annoy |
| O-013 | onboarding | Klar.Select | annoy | The popup of a `Select` with descriptions (payment terms: "Prepaid" + "Paid before shipping") is only as wide as the field, so descriptions are cut ("Paid before shippi..."). | cosmetic | Let the popup grow to content (`min-width: anchor-size`, no max). | annoy |
| O-014 | onboarding | Klar.InlineEdit | bug | After a failed save the inline edit always offers "Try again", also when the problem is a version conflict or a validation problem from the server (kinds `Remote.conflict`, `Remote.validation`), which `Remote.isRetryable` says are not worth retrying (and `Form.status`, `Select`, `ErrorState` all follow that rule). Pressing it can only fail the same way. There is no concept of "the record changed": I show an `Alert` beside the field. | found in the browser, 0 iterations (worked around with the Alert) | Hide "Try again" for non-retryable kinds, as `Form.status` does; document the conflict case for inline edits. | annoy |
| O-015 | onboarding | Klar.Form (`section`), Klar.Card | bug | `Form.section` draws its title as an `h3` and has no `headingLevel` (Card has one, default 3). Under the page's `h1` every form page, and every page with a Card, fails axe `heading-order` (moderate). I fixed the Card with `Card.headingLevel 2`; the form sections cannot be fixed from outside. | axe run on 5 steps, same finding each | `Form.sectionLevel`/`Form.headingLevel`, or default to `h2`. | annoy |
| O-016 | onboarding | Klar.Form (`errorSummary`) | bug | axe `target-size` (serious, WCAG 2.2) on the links of the error summary: the 6 problem buttons are smaller than 24x24 CSS px. The README says the showcase passes WCAG 2.2 AA. It is the first thing a user sees after a failed submit. | 1 axe run | More padding / min-height on `.klar-form-summary__link`. | slow |
| O-017 | onboarding | Klar.Form / navigation | missing | Task 6 ("leaving a half-filled flow asks for confirmation") can be done for in-app links (`LinkClicked`) and the browser back button (`UrlChanged` + `pushUrl` to restore the address), but closing the tab or reloading cannot be guarded without JavaScript (`beforeunload`). The docs say so honestly (Form.unsavedChanges). I wrote the in-app guard by hand (~45 lines in Main). | ~15 min | A `Klar.Navigation` helper (a guard value that owns the `LinkClicked`/`UrlChanged` dance and the leave dialog), and an optional documented `beforeunload` port snippet for applications that allow JavaScript. | slow |
| O-018 | onboarding | Klar.Select, MultiSelect, TagInput, FileDrop, NumberInput, InlineEdit (all stateful) | boilerplate | The value of a form lives inside ten component states. "Is the form dirty?" needs a `toDraft` that reads each (`Select.value`, `MultiSelect.values`, `TagInput.tags`, `FileDrop.files`, `NumberInput.value`) and a baseline to compare with; "load a saved record" needs the opposite, with a different setter name and argument shape each time (`setValue`, `setValues`, `setTags`, `setFiles`, `NumberInput.setValue (Just x)`, `InlineEdit.setValue`; the stateless `TextInput` is plain strings in my model). About 45 lines for `Draft`, `toDraft`, `load` and `toSupplier`, per form. | ~20 min, 4 helper functions | A uniform `isDirty`/`markClean`/`revert` on stateful controls, or a documented "form model" recipe in `Klar.Form` that shows draft, baseline and load together. | slow |
| O-019 | onboarding | Klar.Form, Klar.Remote, Klar.Validate | missing | Problems from the server tied to fields have no home. `Remote.Problem` describes a whole request (and the `Form.Failed` status shows one title); `Validate.Error` is fine as a shape but only produced by client validators.
