# Klar

An Elm package (`davidtoska/elm-klar`, modules `Klar.*`): a UI toolkit for precise,
data-dense, data-intensive applications. "Klar" is Norwegian for "clear" and "ready".
It is meant to be used by AI agents (Claude, Codex) that build applications: as much
complexity as possible inside the library, as small an API as possible on every
component. It will be published on package.elm-lang.org, so its public API is a promise.

This file is the guide for working on the library. `AI.md` is the guide for building an
application with it; `README.md` is the front page of the package.

## Tech

- Vanilla Elm (0.19.1 to 0.19.3, built with 0.19.3). The library depends only on the
  official `elm/*` packages from the Elm team: core, html, browser, json, time, url (for
  `AppShell` and `LeaveGuard`) and file (for `FileDrop` and the file fields of `Klar.Form`,
  which hand the application the `File` values; the library never reads or sends one).
  `svg`, `bytes`, `parser`, `regex` and `random` are allowed, added only when a component
  needs them. Never `elm/http` (Klar is transport neutral), never a third-party package.
- No ports, no kernel code, no `Debug`, no JavaScript in the library or the example.
- The stylesheet is Elm: `src/Klar/Internal/Css/*.elm`, one module per group, each a CSS
  string; `src/Klar/Internal/Css.elm` puts them together in order. `Klar.stylesheet` draws it.
- Icons are Elm values (`Icon.fromSvg`): `src/Klar/Icon.elm` (the everyday set, by hand) and
  `src/Klar/Icon/*.elm` (generated from Lucide, never edit them; see "Icons").
- English everywhere: documentation, comments, README, example. The components' built-in
  text comes in English and Norwegian Bokmål through `Klar.Locale` (default English).
- Domain-neutral examples: orders, customers, products, warehouses. Nothing about the
  application this library was extracted from.

## The repository

```

                      src/Klar/<Name>/ (its unexposed parts), src/Klar/Internal/ (shared)

```

## Commands

```bash
npm install          # elm, elm-test, elm-format (pinned)
npm run check        # everything: text, classes, icons, docs, AI docs, api, format, tests, showcase
npm test             # elm-test (do not run two at once in one directory)
npm run format       # elm-format, then LF line endings and no byte order mark
npm run gen:ai-docs  # rewrites ai/ from the doc comments (commit the result)
npm run check:compat # Elm 0.19.1 and the oldest allowed dependencies (needs the network)
npm start            # builds and serves the showcase on http://localhost:8000
```

`npm run check` runs, in order: `check:text` (UTF-8, LF, no BOM), `check:classes` (every
`klar-` class the Elm code uses has a rule), `check:icons`, `check:docs` (every exposed name
documented, `elm make --docs` passes), `check:ai-docs` (ai/ is current; AI.md is under 400
lines, names every module, its program compiles), `check:ai-names` (every `Module.name` in
AI.md, README and the doc comments exists), `check-doc-examples --strict` (complete examples
in doc comments compile), `check:api` (no public signature names a type a user cannot name),
`check:format`, the tests, the showcase and its examples build, `check:example-imports` (only
exposed modules; no class or style in `example/src/Examples/`).

Shell pitfalls: backslashes in heredocs are collapsed, so write Elm with lambdas through a
file, not a heredoc; Elm reports compile errors one module at a time.

## The rules

1. **Official packages only** (see Tech). Elm tuples have at most three elements: use records.
2. **The library never imports from an application**; the example imports only exposed modules.
3. **CSS uses tokens** (`var(--klar-...)`), never hard-coded colors, radii, spacing or
   z-indexes. Class names are BEM with the `klar-` prefix (`klar-select__option`,
   `klar-select--open`); state is a modifier class, never a bare `.is-open`.
4. **Keyboard and ARIA from the start**: roles, `aria-expanded`, `aria-selected`, `aria-sort`,
   `aria-live` for async changes, `aria-label` on icon-only buttons. ARIA references always
   name ids that exist.
5. **Every component that shows remote data has every state**: loading, failed (with retry),
   empty, data, refreshing and old (`Remote.Kept`, settled with `Klar.Internal.Freshness`).
   Never add an attribute for "stale" or "refreshing": it comes from the `Remote`.
6. **Text** comes from `Klar.Locale` (`Locale.pick` on an `{ en, nb }` record), never
   hard-wired; every component with built-in text has a `locale` attribute. Never `case` on a
   locale.
7. **Never change what the user typed behind their back.** A number outside its range stays
   with an error; only an explicit action moves it into range.
8. **Keep the public API small and stable.** One way to do each thing, the same name for the
   same idea everywhere. A set that will grow (icons, languages) is an opaque type; an exposed
   union is a closed vocabulary the application matches on (`Remote`, `Rule.Operator`,
   `Table.Direction`, `Theme.Tone` ... `npm run check:api` lists them), and adding to it is a
   major release. Values an application keeps and compares are of its own type, with one
   `Klar.Ids` per id type.
9. Code is formatted by `elm-format`; every exposed module and name is documented.

## API conventions

**View-only components**: `view : List (Attribute msg) -> required -> Html msg`. An attribute
is an opaque `Attribute (Config -> Config)` folded over the defaults; the last one of a kind
wins, except state flags (`loading`, `failed`, `remote`), which add up. Name attributes after
what they set (`placeholder`, `onInput`), bare names for flags (`required`), `Bool` arguments
where the value comes from the model (`disabled`).

**Form controls** embed `Field.Config` (`label`, `hint`, `error`, `errorMaybe`, `required`,
`optionalText`, `labelHidden`, `id`) and wrap themselves with `Field.view` (or
`Field.viewStable` when the control sends messages while the user types).

**Stateful components**: opaque `State` and `Msg`, `init : String -> State` (the DOM id,
unique on the page), `update : Msg -> State -> ( State, Cmd Msg )`,
`view : (Msg -> msg) -> List (Attribute msg) -> State -> Html msg`, accessors and setters.
The state holds the value; the application compares before and after `update`. There are no
out-messages; clicks that are not state changes are plain `msg` attributes. No functions in a
`State` or a `Msg`.

**One implementation, several modules**: when a piece is too big for one page of docs, split
the documentation, not the code: `Klar.Form`, `Klar.Form.Spec` and `Klar.Form.Check` are thin
modules over the unexposed `Klar.Form.Core` (aliases and `name = Core.name` with the
signature and the comment written out).

**Overlays are values**: a dialog, drawer, palette or toast stack returns a
`Klar.Overlay.Overlay`; the page (`AppShell.overlays`, `Overlay.host`) takes the list, knows
when to make the page inert and where focus goes back. A closed dialog stays in the list.

## Popups and focus

- A popup is `klar-anchor` (trigger and popup, the CSS anchor) > `klar-layer` (a transparent
  click-away layer) > `klar-popup` (`position: fixed`, CSS anchor positioning, flips when there
  is no room, an absolute fallback). Never percentage widths on a popup; never `transform`,
  `filter` or `will-change` on an ancestor of one.
- Closing needs no subscription: a click on the layer closes. Popup content that must stay
  open decides on the layer whether the click started inside. Escape and Tab are handled on
  the layer (`Internal.onKeysPassive`); the popup is focused on open (`Internal.focus`) and
  focus returns to the trigger.
- Lists in popups have a fixed row height (`--klar-option-h`) for `Internal.ensureVisible`;
  thousands of rows go through `Klar.VirtualList`.
- Focus must survive a re-render: an element with focus that is replaced or moved drops
  focus to `BODY`. Test with real key presses and look at `document.activeElement`. A retry
  button that goes away takes focus with it; `Klar.focus` is the application's way back.
- Lost focus has no event: `Modal` keeps an invisible guard that the stylesheet animates
  while no overlay holds focus (`animationstart` is the message). A new surface that can
  hold focus is added to that selector in `Klar.Internal.Css.Overlay`.

## Tricks for plain Elm

- `Internal.styleVars [ ( "--klar-w", "120px" ) ]` sets custom properties (one `style` per
  element; never mixed with `Html.Attributes.style`). `Internal.attrIf`, `Internal.attrMaybe`.
- `Internal.focus id NoOp` waits one frame, so it works on an element made in the same update.
- Download without JavaScript: a `data:` link with `download`, encoded with
  `Internal.percentEncode` (never `Url.percentEncode`, which throws on half of an emoji).
- Timers: `Process.sleep ms |> Task.perform`, with a counter to drop stale ones.
- Graphics without `elm/svg`: icons and chart lines are SVG written as a `data:` URI and used
  as a CSS mask; never `Html.Attributes.property "innerHTML"`.
- `//` cuts to 32 bits: never on milliseconds or large amounts.
- In a `Browser.application` every `<a href>` click is a `UrlRequest`: anything that is not a
  navigation is a button. A link with a `target` is not intercepted.
- Page-level keys go through `Klar.Shortcut`. `<html lang>` cannot change, so `AppShell` puts
  `lang` on its own root. A file dropped outside a drop zone replaces the page:
  `AppShell.onStrayDrop` cancels it.

## Documentation

Elm packages are documented by their source, and the doc comments are also what `ai/` is
made from, so they are written for an AI reader.

- **Module doc**: one sentence on what it is for; a `Use when:` and a `Do not use when:` line
  (a decision that names the alternative); for a module with a `State`, a `Quick path:` line;
  a short realistic example (for a stateful component: the model field, the update branch, the
  view call); then `# Sections` with `@docs` lines, the `view` first.
- **Every exposed name**: what it does for the user of the library in one to three sentences,
  with its default; what the `String` of an `init` is, what a `msg` receives.
- A claim (what a component waits for, a heading level, a default) is read from the code or
  measured. There is one way to do each thing: AI.md, the examples and the module docs show
  the same wiring. Link modules as `[Klar.Button](Klar-Button)`.
- After changing a doc comment: `npm run gen:ai-docs`, then `npm run check`.

## Adding a component

1. `src/Klar/<Name>.elm`: module doc with an example, opaque `Attribute`, built-in text
   through `Locale.pick`, keyboard and ARIA from the start. Add it to `exposed-modules`.
2. Its CSS in the matching `src/Klar/Internal/Css/<Group>.elm` (tokens only, `klar-<name>`).
3. A section on the showcase page of its group in `example/`, and tests for its pure logic.
4. `npm run check`, then try it in a browser with the mouse and the keyboard, near the bottom
   edge and inside a scrolling container, at 1024 px, with no console errors.

## Icons

The modules under `src/Klar/Icon/` are generated. To add one: put its Lucide name in a group
of `scripts/icons-spec.mjs` (names after a group's `limit` are a reserve), then

```bash
mkdir lucide && cd lucide && npm pack lucide-static && tar xzf lucide-static-*.tgz
cd .. && node scripts/generate-icons.mjs lucide/package
npm run format && npm run check
```

An icon of the everyday set is written by hand in `src/Klar/Icon.elm` with `Icon.fromSvg`
and listed in `all`; add one there only when a component needs it. The license texts of
Feather and Lucide are in `LICENSE`.

## Releasing

Never commit, tag, push or publish without the owner asking; 1.0.0 is permanent.

1. The repository is `github.com/davidtoska/elm-klar` (the package name must match).
2. `npm run check` and `npm run check:compat` green; read README, AI.md and CHANGELOG once more.
3. `elm diff` and `elm bump` (the first release is `1.0.0`), a line in `CHANGELOG.md`, then
   `git tag -a <version> -m <version>`, `git push origin main --tags`, `elm publish`.

A published version can never be changed or removed.
